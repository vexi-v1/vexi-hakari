# AI usage disclosure

ETHGlobal asks teams to disclose which code and assets AI generated, and spec-driven projects to attach their specs and
prompts. This file is that record. Times are JST and match `git log` (the commits are the ground truth).

## How the project was built

Eric (the only human on the team) wrote the specs in `docs/` with Claude (Opus 5.5) during 2026-09-25 and committed
them at 21:46 and 21:52 JST, then handed the build to Claude Code (model: Claude Fable 5.1) with the brief below,
reviewed each gate's evidence, and directed the review and rework described in the last rows. Every code commit was
authored through Claude Code. Commits carry a `Co-Authored-By` trailer except `9f1f145` and `9687370`, whose messages
were written to files and committed without the trailer by mistake; they are Claude Code's work like the others. All
code in this repository was written during the event; the specs were written from the team's own research and public
chain data.

### The brief given to Claude Code (2026-09-25, 21:58 JST, translated from Chinese)

> Take over the ETHGlobal Tokyo 2026 entry vexi-aqua and build it. Read README, SPEC, spec-1inch, plan, demo and
> facts in that order. Hard rules: Robinhood Chain 4663 is read-only and every transaction goes to a local anvil fork;
> From Scratch, no pre-event code from any repo; never read or print .env or keys; commit every small step with
> `git add -- <files>` and never amend or force-push; every AI change gets a row in docs/ai-usage.md; SwapVM-derived
> files live in contracts/swapvm under the Degensoft license; English only inside the repo. Gates: G0 build + pinned
> deps + pinned fork; G1 ship a stock strategy through canonical Aqua and fill it with the deployed v1.0.2 router, pull
> TSLA from an EOA through a minimal app, read the Chainlink TSLA feed; G2 MiniBook + AquaWriter with the five
> invariants; G3 ExposureGuard in a subclassed router and one command for the whole demo. Tests must assert exact
> deltas, never just inequalities.

## Appendix: the review prompts

Every review round used the same two prompts, with the previous round's findings prepended for verification
(translated to English where the brief was in Chinese; the reviews themselves are not part of the repository).

**Sponsor judge.** "You are role-playing a 1inch sponsor judge at ETHGlobal Tokyo 2026 evaluating the 'Build an Aqua
App' prize. Read the repo read-only (never .env, never run the demo), run `forge test`, and judge it as a sponsor
engineer would in a 5-minute booth review plus a 15-minute repo read. Score 1–10: sophisticated position vs wrapper;
depth and correctness of Aqua usage; SwapVM usage (custom instructions, router subclass, canonical router);
demonstration quality; code quality and test rigor; git history and From-Scratch credibility; originality versus
past winners; repo readability. Give the three strongest points, the three biggest risks (disqualification first),
a probability of 1st/2nd/3rd/unplaced, and the top changes under two hours each. Cite file paths and line numbers."

**Technical auditor.** "You are an AI technical reviewer auditing the project before submission, read-only. For each
contract give a correctness and security review (settlement, pro-rata close, exercise window, decimals and strike
maths, reentrancy, rounding, promise accounting, access control, dock and allowance changes, quote/swap consistency,
direction handling, rounding and caps in the skew, Chainlink round search, opcode table construction), classified
critical / should-fix / nit and demo vs production. Judge test rigor (do the tests prove the five invariants, do they
assert exact deltas, what is untested, what is tautological), compliance (From Scratch, licensing, AI disclosure,
secrets, official Aqua/SwapVM contracts), list the technologies used with versions and addresses, and give a
probability of placing with the three fixes you would make first. Be exact and skeptical."
