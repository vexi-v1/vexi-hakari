# HAKARI（秤）：一個價格要花多少錢才能造假

給任何從 Uniswap v4 池讀價的協議一把秤：這個價格現在推得動嗎、推它要花多少、要不要信它。

## 1. 要解決的問題（有數字）

每個「從 v4 池讀價」的協議（選擇權、借貸、永續、清算）都默認一件事：池子裡的價格是真的。這件事在三種情況下不成立，而且每一種我們都量過或查過：

| 情況 | 發生什麼 | 量到的數字 | 來源 |
| --- | --- | --- | --- |
| A 原子推價 | 協議讀即時價（或一個會在安靜時累積「可移動額度」的限速器）。攻擊者在**同一筆交易**裡推池、對著被推動的報價成交、再推回來。可用閃電貸，不用撐住價格。 | 一個 Robinhood 測試網上的選擇權場地實測：每口賺 **+87 bps**（扣費後）；原子化探針：安靜 30 秒後推 5% → 限速器走 +299 bps，攻擊者每口淨賺 **+181.7 bps**；安靜 5 秒 → +17.7 bps | 內部量測 |
| B 撐住的推價 | 協議讀 TWAP。攻擊者把池子推住幾秒到幾分鐘，每秒的第一筆 swap 都把被推的價格記進去。沒有截斷時，**一個觀測值可以跳任意遠**，薄池撐短時間就能拉動 TWAP。 | OpenZeppelin `BaseOracleHook(2 * MAX_TICK)` 等於關掉截斷（1,774,544 ticks，任何跳動都不會被限制） | `uniswap-hooks/src/oracles/panoptic/libraries/Oracle.sol` L38–60 |
| C 被圍住的池 | 股票代幣週末鑄造／贖回關閉，沒有套利者手上有硬參考價，整個 float 大部分被一個池吸走。推價幾乎不用錢，因為沒人會把它推回來。 | HIMS（Robinhood Chain 4663）：8/30（週日）HIMS/USDG v4 池從 **29.38** 漲到 **54.50 USDG**，NYSE 收盤 **28.84**；池中 HIMS 本金從 **2,606** 掉到 **32** 顆；週一首筆 mint 後回到 29.31 | 鏈上重建（2026-09-25）；NYSE 收盤為二手資料 |

價格那張的點位：區塊 50,265,277 / 50,415,299 / 50,444,948 / 50,490,000 / 50,772,447。本金是用 position 的 liquidity、價格與區間上下界推算的曲線本金，不是「1% 價差內可賣的數量」。同一期間 HIMS 流進 BONER/HIMS 池（本金 7,068 → 12,796），是搬家不是鎖死。價格／出區間效應佔 90.76%、LP 部位變更佔 9.24%（Shapley 會計分解，不是因果識別）。

**真正的難處是一個取捨，不是一個 bug。**把截斷打開（例如 Panoptic 在 wstETH/ETH 用每個觀測最多移動 250 ticks）可以擋住 B 和 C，但真的暴漲暴跌時，截斷後的價格會落後，結算就會用到舊價格、對誠實的持有人不公平。這正是有些協議故意關掉截斷的原因。**HAKARI 要回答的是：一個價格的移動，值不值得信任，取決於偽造它要花多少錢，跟偽造成功能賺多少錢比。**

## 2. 核心觀念：三層信任

第一層 · 對付 A · 跨過區塊邊界的價格：oracle hook 在「每秒第一筆 swap 之前」記錄當時的 tick。推了又推回來、發生在同一秒內的，一筆都不會被記到。即時價（`slot0`）和會累積額度的限速器都沒有這層保護。

第二層 · 對付 B · 每一步最多走多遠：截斷後的序列每個觀測最多移動 Δ ticks。攻擊者要撐住至少 `d/Δ` 秒才能把截斷後的價格拉動 d。Δ 用這個池子自己的歷史來校準（誠實交易的每秒移動有 99% 落在 Δ 以內）。

第三層 · 對付 C 與取捨 · 偽造成本對上利益：原始序列和截斷序列不一致時，量出「把價格推到原始序列那裡、撐過整個窗口要花多少錢」。成本大於這次結算的利益，就信原始價；小於，就用截斷價。套利關門（週末股票）時，成本會崩掉，這層會自動轉向保守。

## 3. 要做的四個東西

### 3.1 `PushCostLens`（Solidity）：推一個池子要花多少

對任何 v4 池（官方 PoolManager）回答：「把價格往上／往下推 x%，再推回原位，需要多少資金、會付掉多少手續費」。兩種模式：

| 函式 | 怎麼算 | 給誰用 |
| --- | --- | --- |
| `quotePush(PoolKey key, int24 ticks, bool up) → PushQuote` | **精確模擬**：在 `unlockCallback` 裡先用 `sqrtPriceLimitX96 = 目標價`、超大 exact-input 的 `swap` 推到目標，記錄 `BalanceDelta`；再用「原價」當 limit 推回來，記錄；最後 `revert` 帶出結果（V4Quoter 的做法），狀態全部還原。會真的執行池子上的 hook 與手續費。 | 鏈下 `eth_call`：量表服務、網頁 |
| `depthToMove(PoolKey key, int24 ticks, bool up) view → (amountIn, feePaid)` | **view 走 tick**：用 StateView 讀 `slot0`、`liquidity`、`getTickBitmap`、`getTickLiquidity`，逐段用 `SqrtPriceMath.getAmount0Delta / getAmount1Delta` 累加到目標 tick，加上 LP fee。不需要 unlock，可以在其他交易裡呼叫。 | 鏈上：`SafeSettle` |

```
struct PushQuote {
    uint160 sqrtPriceStart;  uint160 sqrtPriceTarget;
    uint256 amountIn;        uint256 amountOut;      // push leg
    uint256 amountBackIn;    uint256 amountBackOut;  // return leg
    int256  netCostInQuote;  // what the round trip costs, valued in the quote currency at the start price
}
function quotePushLadder(PoolKey calldata key, int24[] calldata ticks, bool up) external returns (PushQuote[] memory);
```

注意：v4 不允許巢狀 `unlock`（`PoolManager.sol` 在已 unlock 時會 revert `AlreadyUnlocked`），所以 `quotePush` 不能在別人的 unlock 裡被呼叫；鏈上一律用 `depthToMove`。

**第 6 小時的自我檢查：**賽前在 4663 fork（區塊 71,937,777）上量過「在 TSLA/USDG 池買 10 顆 TSLA 再賣回，淨損 −26.560259 USDG」。在同一個區塊，`quotePush` 用推 10 顆的量算出的來回成本應該要接近這個數。對不上就代表方向、單位或手續費算錯了。

### 3.2 `HakariOracleHook`（Solidity）：兩條序列都留

```
contract HakariOracleHook is BaseOracleHook {        // OpenZeppelin uniswap-hooks, MIT
    constructor(IPoolManager m, int24 maxAbsTickDelta) BaseHook(m) BaseOracleHook(maxAbsTickDelta) {}
    /// geometric TWAP ticks over [now - window, now], raw and truncated
    function twaps(PoolId id, uint32 window) external view returns (int24 rawTick, int24 truncTick);
}
```

- 權限只開 `afterInitialize` 和 `beforeSwap`，位址位元 `0x1080`。沒有 return-delta、沒有動態費，Uniswap 路由會自動收錄。
- `BaseOracleHook.observe(secondsAgos, poolId)` 本來就一次回傳兩組累積值（原始、截斷），`twaps` 只是把它包成兩個 tick。
- Δ 是 immutable，**一個 hook 合約只有一個 Δ**。要不同的 Δ 就部署不同的 hook（例如「股票級」與「memecoin 級」兩顆），各自挖 salt。
- 部署在**官方 PoolManager** `0x8366…0951`：在 4663 的 fork 上跑 demo，並在測試網 46630 上真的部署一次（同一個位址也有官方 PoolManager，bytecode 相同），拿到公開的 tx hash。
- Demo 用的池子：在 fork 上新建一個掛這顆 hook 的「影子池」，照真實池的流動性分布放進幾段區間（從真實池的 tick liquidity 讀出形狀）。真實池本身沒有這顆 hook，所以只能影子化。

### 3.3 `SafeSettle`（Solidity）：示範用的結算決策

一個簡單的現金結算合約（示範用，不是產品），在到期時決定用哪個價格，並把「為什麼」寫在事件裡。

```
function settlePrice(PoolKey calldata key, uint32 window, uint256 oiAtStake)
    external view returns (int24 tickUsed, bool usedRaw, uint256 costToFake, uint256 gainIfFaked);
// 1. (raw, trunc) = hook.twaps(id, window)
// 2. d = |raw - trunc|;  if d <= TOLERANCE_TICKS → use raw (nothing to explain)
// 3. costToFake = CostModel.v0(lens.depthToMove(key, d, raw > trunc), holdSeconds(d, Δ), arbOpen)
// 4. gainIfFaked = oiAtStake × S × (1.0001^d − 1)      // payout moved by the fake
// 5. costToFake > gainIfFaked → raw (a genuine jump; truncation would only lag)
//    otherwise              → trunc (cheap to fake; do not pay on it)
event Settled(PoolId id, int24 rawTick, int24 truncTick, bool usedRaw, uint256 costToFake, uint256 gainIfFaked);
```

`arbOpen` 由呼叫方傳入，demo 時由量表提供：股票代幣在鑄造窗口關閉期間為 false。這個旗標是「信任量表」的地方，要在 README 寫清楚。

### 3.4 量表服務 + 網頁（TypeScript）：把成本畫出來

- **成本階梯：**對 4663 上的一串池（TSLA/USDG、NVDA/USDG、HIMS/USDG、幾個 memecoin 池）用 `quotePushLadder` 算推 1% / 5% / 10% 的來回成本，每 N 個區塊更新一次。
- **Δ 校準：**讀池子的 `Swap` 事件，算「每秒 tick 變動」的分布，取第 99 百分位當建議的 Δ（Panoptic 的方法）。
- **HIMS 週末重播：**從 HIMS/USDG 池的 `Initialize` 到區塊 50,772,447，用 `ModifyLiquidity` 事件重建每個 position（sender、tickLower、tickUpper、salt），在第 1 節那五個觀測點算「推 10% 要多少 USDG」，畫出週末成本崩落的曲線。公開 RPC 讀不到那麼舊的**狀態**，但讀得到**事件**，所以要從事件重建，不能 fork 那天。這支蒐集程式要賽中重寫。
- **鑄造窗口旗標：**Robinhood 股票代幣鑄造／贖回在週六 02:00 到週一 02:00（CET）關閉（二手資料）。HIMS 案例裡，關閉後的第一筆 mint 是 2026-08-31 00:43:30 UTC，吻合。另外可以讀 Robinhood 官方資產 API 的 `tradingCapabilities`（market／extended／overnight）。
- **網頁：**貼一個 pool id → 看它現在「推 5% 要多少錢」、這一刻是否被圍住、建議的 Δ；另一頁是 HIMS 重播和 `SafeSettle` 的決策紀錄。評審要能自己玩。

## 4. 成本模型 v0（寫明假設，之後再修）

要把一個 W 秒窗口的原始 TWAP 推動 x ticks，攻擊者要讓池子偏離 d ticks、撐 s 秒，且 `d · s ≥ x · W`（s ≤ W）。

| 項目 | v0 怎麼算 | 假設 |
| --- | --- | --- |
| 推上去再推回來 | `roundTrip(d)` = `depthToMove` 往返的手續費 ＋ 價格衝擊的損失 | 精確，來自池子的真實流動性 |
| 撐住的維持成本 | 套利開著：每秒被套利者拉回，要重推一次 → 約 `s × roundTrip(d)`；套利關著：約 0 | 最粗的一環，用 HIMS（關）和平日 TSLA（開）兩個案例校準 |
| 截斷序列要撐多久 | 截斷每個觀測最多走 Δ，每秒最多一個觀測 → 要把截斷價拉動 d 至少 `⌈d/Δ⌉` 秒 | 來自 `Oracle.transform`，精確 |
| costToFake(x) | `min over (d, s)`：`roundTrip(d) + (arbOpen ? s × roundTrip(d) : 0)` | 保守下界，寧可判「便宜」 |
| gainIfFaked(x) | `OI × S × (1.0001^x − 1)` | 對深價內的一口選擇權，delta 約 1 |

由此可以直接導出**最大安全未平倉量**：`n_max = min over x of costToFake(x) / (S × (1.0001^x − 1))`。這就是借貸協議用流動性決定供給上限的同一個道理。

## 8. 風險與未解

- **成本模型 v0 很粗。**「撐住的維持成本」取決於套利者，我們只能給下界。README 要寫成「報告 ＋ 可替換的決策規則」，不要寫成保證。
- **鏈上 `depthToMove` 的 gas。**跨很多 tick 時很貴，要設走 tick 的上限，超過就回報「深到不用算」。
- **舊狀態讀不到。**公開 RPC 對 8/30 的舊狀態回 unavailable，HIMS 只能用事件重建。
- **股票代幣的轉帳限制。**賽前的 fork 測試證明 TSLA 在 v4 上可以正常轉帳；影子池用 fork 上的資金，G1 時一併確認。
- **評審口味。**這個獎最近 6 個得獎作品只有 1 個是 hook，其他多半是真的在用 Uniswap 的產品，所以網頁要能讓評審自己貼 pool 玩，不能只有 forge 測試。
- **From Scratch 界線。**知識可以帶進來，程式碼不行。賽前的蒐集程式要重寫。
